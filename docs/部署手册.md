## 四、配置文件详解

### 4.1 后端 `application.yml`

文件位置：`mr-board/mr-board-web/src/main/resources/application.yml`

核心配置项说明：

```yaml
server:
  port: 8080                     # 后端服务端口

spring:
  profiles:
    active: dev                   # 激活的配置文件：dev | test | prod
  
  datasource:
    url: jdbc:mysql://localhost:3306/mr_board?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: ${MYSQL_PASSWORD:MrBoard@2026}   # 支持环境变量注入
    hikari:
      minimum-idle: 5
      maximum-pool-size: 20

  data:
    redis:
      host: localhost
      port: 6379
      password: ${REDIS_PASSWORD:}
      database: 0

jwt:
  access-secret: ${JWT_ACCESS_SECRET:mr-board-access-secret-key-2026-07-25-very-long}
  refresh-secret: ${JWT_REFRESH_SECRET:mr-board-refresh-secret-key-2026-07-25-very-long}

sync:
  proxy:
    enabled: ${SYNC_PROXY_ENABLED:false}    # Git 平台同步是否启用代理
    host: ${SYNC_PROXY_HOST:127.0.0.1}
    port: ${SYNC_PROXY_PORT:7897}

app:
  cors:
    allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:5173,http://localhost:3000}
```

**多环境配置：**

| Profile | 数据库地址 | Redis 地址 | 日志级别 | 用途 |
|---------|-----------|-----------|---------|------|
| `dev` | `localhost:3306` | `localhost:6379` | DEBUG | 本地开发 |
| `test` | `mysql:3306` (容器) | `redis:6379` (容器) | INFO | Docker 测试 |
| `prod` | 生产数据库地址 | 生产 Redis 地址 | WARN | 生产环境 |

### 4.2 前端 `vite.config.ts`

```typescript
export default defineConfig({
  server: {
    port: 5173,
    strictPort: true,        // 固定端口，防止漂移导致 CORS 失效
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
      },
      '/ws': {
        target: 'ws://localhost:8080',
        ws: true,
      },
    },
  },
})
```

### 4.3 Nginx 反向代理

生产环境使用 Nginx 统一入口：

- `80/443` → Nginx
- `/api/*` → 后端 `8080`
- `/ws/*` → 后端 WebSocket
- `/*` → 前端静态资源

## 五、部署方式

### 方式一：Docker Compose 一键部署（推荐生产/测试）

#### 步骤 1：克隆代码

```bash
git clone https://github.com/taoshop/mr-board.git
cd mr-board
```

#### 步骤 2：配置环境变量（可选）

创建 `.env` 文件：

```bash
# 数据库密码
MYSQL_PASSWORD=MrBoard@2026

# Redis 密码（如配置了 requirepass）
REDIS_PASSWORD=

# JWT 密钥（生产环境务必修改）
JWT_ACCESS_SECRET=your-access-secret-key-min-32-chars-long
JWT_REFRESH_SECRET=your-refresh-secret-key-min-32-chars-long

# Git 同步代理（如需翻墙访问 GitHub）
SYNC_PROXY_ENABLED=false
SYNC_PROXY_HOST=127.0.0.1
SYNC_PROXY_PORT=7897
```

#### 步骤 3：启动全栈服务

```bash
docker compose up -d --build
```

服务启动顺序（通过 `depends_on` + `healthcheck` 自动编排）：

1. `mysql` → 健康检查通过后
2. `redis` → 健康检查通过后
3. `backend` → 编译启动 Spring Boot
4. `frontend` → 构建 Vue 静态资源
5. `nginx` → 对外暴露 80/443

#### 步骤 4：验证部署

```bash
# 查看服务状态
docker compose ps

# 查看后端日志
docker compose logs -f backend

# 访问系统
curl http://localhost/api/actuator/health
# 预期返回：{"status":"UP"}
```

默认管理员账号：

- 用户名：`admin`
- 密码：`Admin@123`

#### 步骤 5：停止服务

```bash
docker compose down          # 保留数据卷
docker compose down -v       # 删除数据卷（清空数据库）
```

### 方式二：开发环境本地部署（前后端分离）

#### 后端启动

```bash
cd mr-board/mr-board-web

# 方式 A：Maven 直接运行（推荐开发调试）
mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 方式 B：先打包再运行
mvn clean package -DskipTests
java -jar target/mr-board-web-*.jar --spring.profiles.active=dev
```

后端将监听 `http://localhost:8080`。

#### 前端启动

```bash
cd mr-board-frontend

# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

前端将监听 `http://localhost:5173`，并通过 Vite Proxy 转发 `/api` 到后端。

#### 数据库准备

```bash
# 启动 MySQL 和 Redis（Docker 方式）
docker run -d \
  --name mr-board-mysql \
  -e MYSQL_ROOT_PASSWORD=MrBoard@2026 \
  -e MYSQL_DATABASE=mr_board \
  -p 3306:3306 \
  mysql:8.0 \
  --character-set-server=utf8mb4 \
  --collation-server=utf8mb4_unicode_ci

docker run -d \
  --name mr-board-redis \
  -p 6379:6379 \
  redis:7-alpine

# 导入初始化 SQL
mysql -h127.0.0.1 -uroot -p'MrBoard@2026' mr_board < mr-board/db/init.sql
```

### 方式三：手动服务器部署（传统 Jar + Nginx）

#### 步骤 1：编译打包

```bash
# 后端
cd mr-board
mvn clean package -DskipTests
# 产物：mr-board-web/target/mr-board-web-*.jar

# 前端
cd ../mr-board-frontend
npm install
npm run build
# 产物：dist/ 目录
```

#### 步骤 2：部署后端

```bash
# 上传 jar 到服务器
scp mr-board-web/target/mr-board-web-*.jar user@server:/opt/mr-board/

# 使用 systemd 管理（示例）
cat > /etc/systemd/system/mr-board.service << 'EOF'
[Unit]
Description=MR Board Backend
After=network.target

[Service]
Type=simple
User=mrboard
WorkingDirectory=/opt/mr-board
Environment="SPRING_PROFILES_ACTIVE=prod"
Environment="MYSQL_PASSWORD=YourStrongPassword"
Environment="JWT_ACCESS_SECRET=your-access-secret"
Environment="JWT_REFRESH_SECRET=your-refresh-secret"
ExecStart=/usr/bin/java -jar /opt/mr-board/mr-board-web.jar
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable mr-board
systemctl start mr-board
```

#### 步骤 3：部署前端

```bash
# 将 dist 上传到 Nginx 目录
rsync -avz dist/ user@server:/usr/share/nginx/html/mr-board/

# 配置 Nginx（参考 nginx/nginx.conf）
nginx -t
systemctl reload nginx
```

## 八、常见问题

### Q1：前端启动后登录报错 CORS

**原因**：Vite dev server 端口漂移或不在后端白名单。

**解决**：

1. 检查 `vite.config.ts` 中 `strictPort: true` 已启用
2. 检查后端 `application.yml` 中 `app.cors.allowed-origins` 包含前端地址

### Q2：数据库连接失败 `Public Key Retrieval is not allowed`

**解决**：已在 JDBC URL 中配置 `allowPublicKeyRetrieval=true`，确认完整 URL：

```
jdbc:mysql://localhost:3306/mr_board?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useUnicode=true&characterEncoding=utf-8
```

### Q3：同步 GitHub 报错 `Invalid HTTP method: PATCH`

**原因**：JDK 内置 `HttpURLConnection` 不支持 PATCH。

**解决**：项目已引入 `httpclient5` 依赖，`GitHubClient` / `GitLabClient` 已替换为 `HttpComponentsClientHttpRequestFactory`。

### Q4：报表 CI 成功率始终为 0%

**原因**：`ci_jobs.started_at` 为 NULL，日报统计按 `started_at` 范围过滤。

**解决**：

1. 确认 `GitHubClient` / `GitLabClient` 已映射 `startedAt`
2. 修复历史数据：`UPDATE ci_jobs SET started_at = created_at WHERE started_at IS NULL`
3. 重新触发报表计算：`POST /api/reports/admin/trigger-summary`

### Q5：账号锁定 "请15分钟后重试"

**原因**：连续 5 次登录失败后 Redis 锁定。

**解决**：

```bash
# 清除 Redis 锁定键
docker exec mr-board-redis redis-cli DEL "login:fail:admin"
```
