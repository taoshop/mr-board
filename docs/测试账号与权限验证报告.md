## 七、常见问题

### 7.1 登录后看板为空（Developer / Reviewer）

**原因：** `applyDataScope` 会根据当前登录用户的 `platform_username` 过滤 `authorName`。如果本地同步的 MR 数据中 `authorName` 不是 `dev1` 或 `reviewer1`，则这 2 个账号看不到任何 MR。

**解决方案：**
1. 使用 `admin` 账号登录，确认看板中 MR 的 `authorName` 字段值。
2. 创建与该 `authorName` 一致的测试账号（修改 `platform_username`），或通过「用户管理」将现有用户的 `platform_username` 改为对应值。
3. 或直接给 `dev1`/`reviewer1` 的 `platform_username` 赋值为实际 MR 数据中的作者名。

### 7.2 密码无法登录

**原因：** 如果 `password` 字段的哈希值与 `BCryptPasswordEncoder` 不匹配（如 rounds 不同）。

**解决方案：** 通过 `admin` 账号登录后，在「用户管理」页面重置目标用户的密码（前端会调用 `PasswordEncoder` 重新编码）。

### 7.3 角色未生效

**原因：** `user_roles` 表未正确关联，或 JWT Token 中未携带角色信息。

**验证 SQL：**

```sql
SELECT u.username, r.code, r.name
FROM users u
JOIN user_roles ur ON u.id = ur.user_id
JOIN roles r ON ur.role_id = r.id
WHERE u.username = 'dev1';
```

## 九、修复记录（2026-07-28）

### 9.1 问题描述

`dev1`（Developer 角色）登录后，前端看板页面弹出多条「禁止访问」提示（HTTP 403）。

**根因：** 数据库角色编码为 `dev`，但后端 Spring Security 注解使用 `hasAnyRole('DEVELOPER')`（查找 `ROLE_DEVELOPER`）；`CustomUserDetailsService` 将角色编码直接映射为 `ROLE_DEV`，导致不匹配。同时前端 `DashboardView.vue` 使用 `includes('developer')` 判断开发者权限，后端返回 `dev` 导致前端也无法识别。

### 9.2 修复内容

| 文件 | 修改说明 |
|---|---|
| `mr-board-system/.../CustomUserDetailsService.java` | 加载用户角色时，将 `dev` 统一映射为 `ROLE_DEVELOPER` |
| `mr-board-system/.../AuthController.java` | 新增 `normalizeRoleCodes` 方法，在返回 JWT / 用户信息时把 `dev` 替换为 `developer` |
| `db/init.sql` | 种子数据角色编码 `'dev'` 改为 `'developer'`（长期规范） |
| `mr-board-web/pom.xml` | 确认 `spring-boot-maven-plugin` 已配置，使用 `mr-board-web/target/...jar` 启动 |
| `mr-board-system/.../GitSourceController.java` | 移除类级别 `hasRole('ADMIN')`；查询接口改为 `hasAnyRole('ADMIN','PM','TECHLEAD','DEVELOPER','REVIEWER')`；写操作保留 `ADMIN/PM/TECHLEAD` |
| `mr-board-system/.../SyncLogController.java` | 查询接口权限从 `ADMIN/PM/TECHLEAD` 扩展为 `ADMIN/PM/TECHLEAD/DEVELOPER/REVIEWER`，与前端菜单权限一致 |
