# Git源同步数据 — 看板状态分类判断逻辑文档

## 一、概述

本文档梳理 MR（Merge Request）看板中 **6 种状态** 的分类判断逻辑。状态计算基于 Git 平台同步数据，由 `BoardStatusCalculator` 统一决策，在 `SyncService` 同步流程中执行，结果写入 `mrs.board_status` 字段。

**核心设计原则（v2）：**
- CI 状态作为卡片上的**独立视觉维度**（图标/颜色），不再驱动列归属
- 取消独立的「CI 检查中」列，CI 失败作为冲突原因进入 `conflict` 列
- 手动拖拽状态可覆盖自动计算结果（终态 MR 除外）

## 二、状态分类总览

| 状态码 | 中文名称 | 前端标签 | 前端颜色 | 适用场景 |
|---|---|---|---|---|
| `merged` | 已合并 | 已合并 | `#409eff` (primary) | 平台已合并 |
| `closed` | 已关闭 | 已关闭 | `#909399` (info) | 平台已关闭 |
| `conflict` | 冲突待解决 | 冲突待解决 | `#f56c6c` (danger) | 合并冲突 / CI 失败 / approved 但不可合并 |
| `pending_review` | 待 Review | 待 Review | `#909399` (info) | 无 reviewer / 未开始评审 / Draft / WIP |
| `reviewing` | Review 中 | Review 中 | `#e6a23c` (warning) | 评审中 / 有修改请求 |
| `ready` | 可合并 | 可合并 | `#67c23a` (success) | 已 approved 且可合并 |

## 三、核心判断逻辑（BoardStatusCalculator）

### 3.1 计算优先级（从高到低）

```
1. platformStatus == "merged"          → merged
2. platformStatus == "closed"          → closed
3. title 以 "draft:" / "wip:" 开头      → pending_review
4. hasConflict == true                 → conflict
5. ciStatus == "failed"                → conflict
6. 无 reviewer 或 approvalStatus == "pending"      → pending_review
7. approvalStatus == "changes_requested" / "reviewing" → reviewing
8. approvalStatus == "approved" 且 mergeable == true → ready
9. approvalStatus == "approved" 但不可合并          → conflict
10. 默认                                 → pending_review
```

### 3.2 决策树（文字版）

```
platformStatus
├── merged → 已合并 (merged)          【终态锁定，最高优先级】
├── closed → 已关闭 (closed)          【终态锁定】
└── open / opened / 其他
    ├── title 以 draft: 或 wip: 开头 → 待 Review (pending_review)
    ├── hasConflict == true          → 冲突待解决 (conflict)
    ├── ciStatus == failed           → 冲突待解决 (conflict) [原因=CI失败]
    └── 以上都不满足 → 按 Review 状态判断
        ├── 无 reviewer 或 approvalStatus == pending
        │                              → 待 Review (pending_review)
        ├── approvalStatus == changes_requested 或 reviewing
        │                              → Review 中 (reviewing)
        ├── approvalStatus == approved
        │   ├── mergeable == true      → 可合并 (ready)
        │   └── mergeable != true      → 冲突待解决 (conflict) [非代码冲突，需处理]
        └── 默认                        → 待 Review (pending_review)
```

### 3.3 关键规则说明

| 规则 | 说明 |
|---|---|
| **终态锁定** | `merged` / `closed` 一旦确认，不受其他字段影响，直接锁定列归属 |
| **Draft/WIP 拦截** | 标题前缀 `draft:` 或 `wip:` 直接视为未就绪，进入 `pending_review` |
| **CI 失败 = conflict** | CI 失败（`ciStatus == failed`）被视为阻塞合并的因素，与代码冲突同列 |
| **CI running/pending 不决定列** | CI 运行中不单独成列，卡片在 review/pending_review 列显示 CI 运行图标 |
| **approved 但不可合并** | 已通过评审但 `mergeable == false`（如需 rebase），进入 `conflict` 列 |

## 四、数据来源与字段映射

### 4.1 数据库实体字段（mrs 表）

| 字段 | 类型 | 数据来源 | 说明 |
|---|---|---|---|
| `platform_status` | String | Git 平台 API | 原始状态：merged / closed / open / opened |
| `board_status` | String | 计算产出 | 看板六列状态 |
| `ci_status` | String | CI 流水线 API | success / failed / running / pending / unknown |
| `has_conflict` | Boolean | Git 平台 API | 是否存在合并冲突 |
| `mergeable` | Boolean | Git 平台 API | 平台是否标记为可合并 |
| `title` | String | Git 平台 API | MR 标题，用于 Draft/WIP 检测 |
| `reviewers` | String | Git 平台 API | 评审人列表，逗号分隔 |
| `approval_status` | String | Git 平台 API | pending / reviewing / approved |
| `manual_status` | String | 用户拖拽 | 手动覆盖状态，非 NULL 时同步保留 |

### 4.2 Git 平台原始字段 → 本地字段映射

#### GitHub Pull Request API

| GitHub 字段 | 本地字段 | 说明 |
|---|---|---|
| `state` | `platform_status` | open / closed / merged |
| `mergeable` | `mergeable` | Boolean，是否可合并 |
| `mergeable_state` 含 `dirty` | `has_conflict` | 冲突检测 |
| `requested_reviewers[].login` | `reviewers` | 请求评审的用户 |
| `reviews[].state` | `approval_status` | APPROVED / CHANGES_REQUESTED / COMMENTED |
| `checks` / `status` API | `ci_status` | 通过 CI jobs 聚合计算 |

#### GitLab Merge Request API

| GitLab 字段 | 本地字段 | 说明 |
|---|---|---|
| `state` | `platform_status` | merged / closed / opened |
| `merge_status` == `can_be_merged` | `mergeable` | Boolean |
| `has_conflicts` | `has_conflict` | Boolean |
| `reviewers[].username` | `reviewers` | 评审人列表 |
| `approvals.approved` / `approved_by` | `approval_status` | approved / reviewing / pending |
| `pipelines` / `jobs` API | `ci_status` | 通过 CI jobs 聚合计算 |

## 五、同步流程（SyncService）

### 5.1 整体流程

```
1. 调用 Git 平台 API 获取 MR 列表 (fetchMRs)
   └── state="all"，确保获取 open / closed / merged

2. 对每个 MR 执行：
   a. 保存/更新 MR 基础信息 (saveOrUpdateMr)
      ├── 首次计算 boardStatus（approvalStatus 暂用默认值 "pending"）
   
   b. 拉取评审信息
      ├── fetchReviewers → 保存 reviewers
      └── fetchApprovalStatus → 保存 approvalStatus
      └── 重新计算 boardStatus（approvalStatus 已更新）
   
   c. 拉取 CI 流水线 (fetchCI)
      ├── 保存每个 CI job
      └── 计算 overallCiStatus
   
   d. 最终计算 boardStatus（ciStatus 已更新）
      └── 应用手动覆盖规则（manual_status）
   
   e. 拉取评论 (fetchComments) → 保存到 mr_comments

3. 更新项目同步时间、MR 计数
```

### 5.2 手动状态覆盖规则

| 场景 | 行为 |
|---|---|
| `manual_status` 为 NULL | 自动计算结果直接写入 `board_status` |
| `manual_status` 非 NULL | 保留手动状态，同步不覆盖 |
| MR 在平台已 merged / closed | 强制覆盖手动状态，同步为终态，并清空 `manual_status` |

### 5.3 同步中 boardStatus 计算次数

一次完整同步中，单个 MR 的 `boardStatus` 最多计算 **3 次**：
1. 保存 MR 基础信息时（reviewers/approval 尚未拉取，用默认值）
2. 拉取 reviewers/approvalStatus 后
3. 拉取 CI 并计算 overallCiStatus 后（最终值）

## 六、CI 状态计算逻辑（calculateOverallCiStatus）

CI 状态由 MR 关联的所有 CI jobs 聚合计算：

| 条件 | 结果 |
|---|---|
| 无 CI jobs | `unknown` |
| 任一 job 状态为 running / pending | `running` |
| 任一 job 状态为 failed | `failed` |
| 存在 cancelled / skipped / canceled，且**没有** success | `unknown` |
| 默认（全部成功） | `success` |

**注意：** `cancelled` / `skipped` 不归类为 `success`，避免误判为通过状态。

## 七、平台差异：GitHub vs GitLab

### 7.1 Reviewers 获取

| 平台 | API 端点 | 说明 |
|---|---|---|
| GitHub | `GET /repos/{owner}/{repo}/pulls/{pr}` | 取 `requested_reviewers[].login` |
| GitLab | `GET /projects/{id}/merge_requests/{iid}` | 取 `reviewers[].username` |

**兜底策略：** 如果 fetchReviewers 返回空，但 MR DTO 中已有 reviewers，则使用 DTO 中的数据。

### 7.2 Approval Status 获取

| 平台 | API 端点 | 映射逻辑 |
|---|---|---|
| GitHub | `GET /repos/{owner}/{repo}/pulls/{pr}/reviews` | 遍历所有 review：<br>• 有 APPROVED 且无 CHANGES_REQUESTED → `approved`<br>• 有 CHANGES_REQUESTED → `reviewing`<br>• 有其他非 COMMENTED 状态 → `reviewing`<br>• 全部 COMMENTED 或空 → `pending_review` |
| GitLab | `GET /projects/{id}/merge_requests/{iid}/approvals` | • `approved == true` → `approved`<br>• `approved_by` 非空 → `reviewing`<br>• 其他 → `pending` |

### 7.3 状态值差异

| 概念 | GitHub | GitLab | 本地统一值 |
|---|---|---|---|
| 开放状态 | `open` | `opened` | `open` / `opened` |
| 已合并 | `merged` | `merged` | `merged` |
| 已关闭 | `closed` | `closed` | `closed` |
| 评审通过 | `APPROVED` | `approved=true` | `approved` |
| 请求修改 | `CHANGES_REQUESTED` | （无直接对应，从评论推断） | `reviewing` |
