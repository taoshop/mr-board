# 可合并状态条件说明

> **版本**: 1.0  
> **关联文件**: `BoardStatusCalculator.java`  
> **关联文档**: [MR 状态生命周期](mr-status-lifecycle.md), [测试验收文档](测试验收文档.md)

---

## 完整优先级表

看板状态由 `BoardStatusCalculator.calculate()` 按 10 级优先级从高到低计算：

```
优先级  条件                                              → 看板列
──────────────────────────────────────────────────────────────────
 1      platformStatus = "merged"                        → merged (已合并)
 2      platformStatus = "closed"                        → closed (已关闭)
 3      title starts with "draft:" / "wip:"              → pending_review (待 Review)
 4      hasConflict = true                                → conflict (冲突待解决)
 5      ciStatus = running / pending / failed             → ci_checking (CI 检查中)
 6      无 reviewer 或 approval = pending                 → pending_review (待 Review)
 7      approval = changes_requested / reviewing          → reviewing (Review 中)
 8      approval = approved  + mergeable = true           → ready (可合并)       ← 可合并
 9      approval = approved  + mergeable = false          → conflict (冲突待解决)
10      默认                                              → pending_review (待 Review)
```

---

## 可合并的必要条件

一个 MR 要进入「可合并」列，必须**同时满足**以下所有条件：

### 1. ❎ 平台已合并/已关闭 — 拦截

```
不进入 merged 或 closed 列
```

平台必须处于 **open / opened** 状态。若已合并或已关闭，优先进入终态列，不再进入可合并。

### 2. ❎ Draft / WIP — 拦截

```
标题不以 draft: 或 wip: 开头
```

草稿状态的 MR 强制归入「待 Review」列。

### 3. ❎ 无冲突

```
hasConflict = false
```

冲突是最高优先级阻塞态（优先级 4），存在冲突时直接进入「冲突待解决」列。可合并要求代码无冲突。

### 4. ❎ CI 未通过 — 拦截

```
ciStatus ≠ running / pending / failed
```

CI 运行中、等待中或失败时（优先级 5），优先进入「CI 检查中」列。可合并要求 CI 为 **success** 或 **unknown**（无可跳过 CI）。

### 5. ✅ Review 已通过

```
approvalStatus = "approved"
```

Reviewer 必须在平台上已 **Approve** 该 MR。若处于 `pending`（未评审）则归入「待 Review」列（优先级 6），`reviewing` / `changes_requested` 则归入「Review 中」列（优先级 7）。

### 6. ✅ Git 平台标记为可合并

```
mergeable = true
```

即使 `approval = approved`，若 Git 平台返回 `mergeable = false`（如需要变基、合并没有通过），也不会进入可合并列，而是进入「冲突待解决」列（优先级 9）。

## 必要条件速查表

| 条件 | 要求 | 不满足时的去向 |
|------|------|---------------|
| platformStatus | open / opened | merged / closed 列 |
| title | 非 draft:/wip: 开头 | pending_review 列 |
| hasConflict | false | conflict 列 |
| ciStatus | success / unknown / cancelled / skipped | ci_checking 列 |
| approvalStatus | approved | pending_review / reviewing 列 |
| mergeable | true | conflict 列 |

## 代码对应

在 `BoardStatusCalculator.java` 第 97-103 行：

```java
// 6. 可合并态
if ("approved".equalsIgnoreCase(approvalStatus)) {
    if (Boolean.TRUE.equals(mergeable)) {
        return "ready";
    }
    return "conflict"; // approved 但不可合并（非冲突原因）
}
```

## 示例场景

| 场景 | platformStatus | hasConflict | ciStatus | mergeable | approvalStatus | 结果 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| 理想合入 | open | false | success | true | approved | **ready** ✅ |
| CI 失败 | open | false | failed | true | approved | ci_checking |
| Review 未通过 | open | false | success | true | pending | pending_review |
| 存在冲突 | open | true | success | false | approved | conflict |
| 不可合并 | open | false | success | false | approved | conflict |
| 已合并 | merged | false | success | true | approved | merged（终态锁定） |
| Draft | open | false | success | true | approved | pending_review |
