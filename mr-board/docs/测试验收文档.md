## 2. 功能特性验收

### 2.1 手动拖拽状态保留

**需求**: 用户将 MR 卡片从「待 Review」拖拽到「Review 中」后，定时同步或手动同步不应将卡片状态重置回「待 Review」。

**实现方案**: 在 `mrs` 表新增 `manual_status` 字段，拖拽时记录手动状态，同步时优先保留。

#### 验收点

| # | 验收条件 | 预期结果 | 验证方式 |
|---|----------|----------|----------|
| 2.1.1 | 拖拽 MR 到非终态（如 pending_review → reviewing） | `manual_status` = reviewing, `board_status` = reviewing | 集成测试 / DB 查询 |
| 2.1.2 | 同步后状态保留 | 同步完成后 `board_status` 仍为 reviewing | 集成测试 / 手动验证 |
| 2.1.3 | 拖拽到终态 merged（需 Git API） | 若无真实 Git API 返回 500，状态不变 | 集成测试 |
| 2.1.4 | 拖拽到终态 closed（需 Git API） | 若无真实 Git API 返回 500，状态不变 | 集成测试 |
| 2.1.5 | 重复拖拽同一状态 | `manual_status` 不变 | 集成测试 |
| 2.1.6 | 连续拖拽（reviewing → ci_checking → reviewing） | `manual_status` 保留最后一次值 | 集成测试 |
| 2.1.7 | board API 返回 `manualStatus` 字段 | API 响应包含该字段 | 集成测试 |
| 2.1.8 | 平台 MR 已合并时清除手动状态 | `manual_status` = NULL, `board_status` = merged | 手动验证 |

### 2.2 CI 状态映射修正

**需求**: CI 失败应归入「CI 检查中」列，而非「冲突待解决」列；cancelled/skipped 应归为 `unknown` 而非 `success`。

#### 验收点

| # | 验收条件 | 预期结果 | 验证方式 |
|---|----------|----------|----------|
| 2.2.1 | CI failed + 有 reviewer | `ci_checking` | 单元测试 |
| 2.2.2 | CI failed + 不可合并 | `ci_checking`（CI 优先） | 单元测试 |
| 2.2.3 | CI cancelled（英式） | `unknown` | 单元测试 |
| 2.2.4 | CI skipped | `unknown` | 单元测试 |
| 2.2.5 | CI canceled（美式） | `unknown` | 单元测试 |
| 2.2.6 | cancelled + success 混合 | `success`（有成功则成功） | 单元测试 |
| 2.2.7 | cancelled + failed 混合 | `failed`（失败优先） | 单元测试 |

### 2.3 看板状态计算完整性

**需求**: 所有 10 种平台状态组合均能正确映射到 7 列看板。

#### 完整状态映射表

```
优先级 条件                                     → 看板列
─────────────────────────────────────────────────────────────
 1     platformStatus = "merged"               → merged (已合并)
 2     platformStatus = "closed"               → closed (已关闭)
 3     title starts with "draft:" / "wip:"      → pending_review (待 Review)
 4     hasConflict = true                       → conflict (冲突待解决)
 5     ciStatus = running/pending/failed        → ci_checking (CI 检查中)
 6     无 reviewer / approval = pending         → pending_review (待 Review)
 7     approval = changes_requested/reviewing   → reviewing (Review 中)
 8     approval = approved + mergeable          → ready (可合并)
 9     approval = approved + !mergeable         → conflict (冲突待解决)
10     默认                                     → pending_review (待 Review)
```

## 5. 端到端手动验证

### 5.1 验证步骤

```bash
# 1. 确认 Docker MySQL 运行中
docker ps | grep mysql

# 2. 全量编译并安装
mvn install -DskipTests

# 3. 启动后端
MYSQL_PASSWORD=MrBoard@2026 mvn spring-boot:run -pl mr-board-web

# 4. 确认服务启动成功
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/mrs?page=1\&size=1
# 期望: 403 (需认证，服务正常)

# 5. 获取 MR 当前状态
docker exec mr-board-mysql mysql -uroot -pMrBoard@2026 mr_board \
  -e "SELECT id, board_status, manual_status FROM mrs WHERE platform_mr_id = 8"

# 6. 登录并获取 Token（通过前端 http://localhost:5180）

# 7. 拖拽 MR 到 Review 中
curl -X PUT "http://localhost:8080/api/mrs/{id}/status" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"boardStatus":"reviewing"}'

# 8. 验证 DB 状态
docker exec mr-board-mysql mysql -uroot -pMrBoard@2026 mr_board \
  -e "SELECT id, board_status, manual_status FROM mrs WHERE platform_mr_id = 8"
# 期望: board_status=reviewing, manual_status=reviewing

# 9. 触发全量同步
curl -X POST "http://localhost:8080/api/admin/git-sources/1/sync?type=full" \
  -H "Authorization: Bearer {token}"

# 10. 等待同步完成（约 5-15 秒）

# 11. 最终验证
docker exec mr-board-mysql mysql -uroot -pMrBoard@2026 mr_board \
  -e "SELECT id, board_status, manual_status FROM mrs WHERE platform_mr_id = 8"
# 期望: board_status=reviewing, manual_status=reviewing (未回退)
```
