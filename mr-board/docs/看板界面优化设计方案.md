# 看板界面优化设计方案（v2 — CI 作为独立维度）

**编制日期：** 2026-07-27  
**目标：** 将 CI 从「看板列」降级为「卡片上的独立标识维度」，看板列只保留流程阶段  
**核心原则：** 看板列 = 流程阶段（Review → Ready → Merged），CI = 客观状态标识，两者解耦

---

## 1. 设计思路：为什么去掉「CI 检查中」列

### 1.1 当前 7 列的问题

Review 和 CI 在真实工作流中是**并行发生**的：
- 开发者 push 代码 → CI 自动触发
- 同时（或稍后）指派 reviewer
- reviewer 评审时，CI 可能还在跑，也可能已经跑完

把 CI 拆成独立列导致：**同一张 MR 在「评审中」和「CI 检查中」之间反复横跳**，看板不稳定，用户无法聚焦。

### 1.2 新 6 列设计

| 列 | 含义 | 进入条件 |
|---|------|---------|
| `pending_review` | 等待 Review | 无 reviewer / review 未开始（CI 可能正在跑） |
| `reviewing` | 正在 Review | 有 reviewer 参与评审中（CI 可能正在跑/已通过/已失败） |
| `conflict` | 阻塞待解决 | 代码冲突 / CI 失败 / approved 但不可合并 |
| `ready` | 可合并 | CI 通过 + Review 通过 + 无冲突 + mergeable |
| `merged` | 已合并 | 终态 |
| `closed` | 已关闭 | 终态 |

**CI 状态作为卡片上的独立标识**：
- 🟠 CI 运行中、⚪ CI 等待中、🔴 CI 失败、🟢 CI 通过
- 这些图标叠加在 `pending_review` / `reviewing` / `conflict` / `ready` 列的卡片上
- 用户一眼就知道「这个 MR 审到哪了，CI 跑完了没」

## 3. 拖拽交互 redesign

### 3.1 拖拽前：可拖拽预览

```
鼠标悬停在可拖拽卡片上时：
┌─────────────────────────────────────────┐
│ ...                                    │
│           ┌──────┐                      │
│           │ ↕️   │  ← 卡片右下角显示拖拽手柄
│           └──────┘                      │
└─────────────────────────────────────────┘
cursor: grab
```

**不可拖拽卡片：**
- `merged` / `closed` 列：cursor: default，hover 无拖拽手柄
- 当前用户无权限的卡片：cursor: not-allowed，tooltip 提示 "仅 ADMIN/TECHLEAD 可操作"

### 3.2 拖拽中：列高亮规则

```
用户从 reviewing 列拖拽一张卡片时：

┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  待 Review  │  │ Review 中   │  │ 冲突待解决  │  │   可合并    │
│   [可拖入]   │  │   [来源]    │  │   [可拖入]   │  │ [条件可拖入] │
│  边框绿色    │  │  卡片半透明  │  │  边框绿色    │  │  边框黄色    │
└─────────────┘  └─────────────┘  └─────────────┘  └─────────────┘

┌─────────────┐  ┌─────────────┐
│   已合并    │  │   已关闭    │
│  [不可拖入]  │  │  [不可拖入]  │
│  边框灰色    │  │  边框灰色    │
│  cursor: 🚫  │  │  cursor: 🚫  │
└─────────────┘  └─────────────┘
```

**列边框颜色语义：**
- 🟢 绿色边框 = 随时可以拖入
- 🟡 黄色边框 = 有条件的拖入（hover 显示条件 tooltip）
- 🔴 红色边框 = 当前卡片禁止拖入（hover 显示原因 tooltip）
- ⚪ 灰色边框 = 终态列，完全不可拖入

### 3.3 拖拽到目标列时的实时校验

```javascript
// DashboardView.vue 中 handleDragOver 增强
function handleDragOver(columnKey: string) {
  dragOverColumn.value = columnKey
  
  const mr = draggingItem.value
  if (!mr) return
  
  const error = canDrop(mr, columnKey)
  if (error) {
    // 列变红，显示禁止图标
    dragOverState.value = { column: columnKey, allowed: false, reason: error }
  } else if (columnKey === 'ready') {
    // 有条件拖入，列变黄
    dragOverState.value = { column: columnKey, allowed: true, conditional: true, reason: '需 CI 通过 + Review 通过 + 无冲突' }
  } else {
    dragOverState.value = { column: columnKey, allowed: true }
  }
}
```

### 3.4 拖拽状态流转速查表（视觉规则）

| 从 \ 到 | pending_review | reviewing | conflict | ready | merged | closed |
|---------|---------------|-----------|----------|-------|--------|--------|
| pending_review | — | 🟢 | 🟢 | 🟡 需CI+Review | 🔴 需权限 | 🔴 需权限 |
| reviewing | 🟢 | — | 🟢 | 🟡 需CI通过 | 🔴 需权限 | 🔴 需权限 |
| conflict | 🟢 | 🟢 | — | 🔴 需先解决冲突 | 🔴 需先解决冲突 | 🔴 需权限 |
| ready | 🟢 | 🟢 | 🟢 | — | 🟡 二次确认 | 🔴 需权限 |
| merged | ⚪ | ⚪ | ⚪ | ⚪ | — | ⚪ |
| closed | ⚪ | ⚪ | ⚪ | ⚪ | ⚪ | — |

- 🟢 绿色 = 自由拖入（CI 状态不影响拖拽，因为 CI 是独立维度）
- 🟡 黄色 = 条件拖入（hover 提示条件）
- 🔴 红色 = 禁止拖入（hover 提示原因）
- ⚪ 灰色 = 终态，不可拖拽

**重要变化：**
- 之前 `ci_checking` 列的「不可拖拽」限制已取消——因为 CI 不再决定列归属
- 现在用户可以**自由拖拽** `pending_review` ↔ `reviewing` ↔ `conflict` ↔ `ready`（只要满足业务规则）
- CI 状态作为**客观事实**展示在卡片上，提醒用户「这个 MR 虽然拖到 ready 了，但 CI 还在跑，暂时不能点合并」

## 6. Review 逻辑可视化详细设计

### 6.1 Review + CI 并行状态机

```
pending_review ──→ reviewing ──→ ready ──→ merged
    │                │   ▲          ▲
    │                │   │          │
    │                ▼   │          │
    │           conflict─┘          │
    │            (CI失败/冲突/需变基) │
    │                               │
    └── CI running ──→ 卡片显示 🟠   │
    └── CI pending ──→ 卡片显示 ⚪   │
    └── CI success ──→ 无图标       │
    └── CI failed ───→ 进入 conflict │
```

**关键规则：**
- CI 状态**不决定列归属**，只决定**是否可以进入 ready**
- `approved + CI running` → 留在 `reviewing`，卡片显示 🟠
- `approved + CI success + mergeable` → 进入 `ready`
- `approved + CI failed` → 进入 `conflict`（阻塞原因 = CI 失败）
- `changes_requested + CI success` → 留在 `reviewing`（等作者修代码）

### 6.2 Reviewer 组件设计

```vue

  <div class="reviewer-badge" :class="statusClass">
    <el-avatar :size="20" :src="avatar" />

      <ElIcon v-if="status === 'approved'"><CircleCheck /></ElIcon>
      <ElIcon v-else-if="status === 'changes_requested'"><CircleClose /></ElIcon>
      <ElIcon v-else-if="status === 'commented'"><ChatDotRound /></ElIcon>
      <ElIcon v-else><Timer /></ElIcon>

```

**样式规则：**
- `approved`：绿色边框 + ✅ 图标
- `changes_requested`：红色边框 + ❌ 图标
- `commented`：蓝色边框 + 💬 图标
- `pending`：灰色边框 + 🕐 图标

## 7. CI 状态关联逻辑详细设计（v2）

### 7.1 CI 不再驱动列跳转，只驱动 ready 准入

```

                          │
                          ├── ciFailed ──→ 如果当前在 ready/reviewing/pending_review
                          │                且 approval=approved
                          │                → 进入 conflict（阻塞合并）
                          │
                          ├── ciSuccess ──→ 如果 approval=approved + mergeable
                          │                 → 进入 ready（可合并）
                          │
                          └── ciRunning ──→ 不改变列归属
                                            → 卡片显示 🟠 运行中图标
```

**与旧方案的核心差异：**

| 场景 | 旧方案（7 列） | 新方案（6 列 + CI 标识） |
|------|--------------|------------------------|
| approved + CI running | 跳转到 `ci_checking` 列 | 留在 `reviewing`，卡片显示 🟠 |
| changes_requested + CI running | 跳转到 `ci_checking` 列 | 留在 `reviewing`，卡片显示 🟠 |
| no reviewer + CI running | 跳转到 `ci_checking` 列 | 留在 `pending_review`，卡片显示 🟠 |
| approved + CI failed | 跳转到 `conflict` | 跳转到 `conflict`，标签显示「CI 失败」 |
| approved + CI success | 跳转到 `ready` | 跳转到 `ready` |

### 7.2 卡片上 CI 图标的实时更新

当前实现是前端轮询（60s），建议增加 WebSocket 实时推送：

```javascript
// 后端 SyncService 在检测到 CI 状态变化时，通过 SyncWebSocketHandler 推送
syncWebSocketHandler.broadcastSyncStatus({
  type: 'ci_status_changed',
  mrId: 42,
  platformMrId: 1347,
  oldCiStatus: 'running',
  newCiStatus: 'success',
  // 注意：不再推送 newBoardStatus，因为 CI 成功不一定导致列变化
  // 只有当 approval=approved + mergeable 时，才同时推送 board_status_changed
  message: 'MR #1347 CI 已通过'
})
```

## 9. 响应式适配

### 9.1 桌面端（>= 1440px）

- 6 列全部展开，每列固定宽度 300-320px（比原来宽，因为列少了）
- 卡片完整展示所有信息
- 拖拽交互完整支持

### 9.2 平板端（768px - 1439px）

- 横向滚动保留，每列 260px
- 卡片精简：Reviewer 只显示头像（hover 显示名字），CI 详情 hover 展开
- 拖拽支持，但触摸设备优先点击操作

### 9.3 窄屏优化（所有尺寸）

- 当一屏无法显示 6 列时，提供「聚焦模式」：
  - 只显示与用户相关的列（我提交的 MR 所在列 + ready 列）
  - 或提供列折叠：合并 `pending_review` + `reviewing` 为「Review 阶段」，合并 `conflict` + `ready` 为「合并阶段」
