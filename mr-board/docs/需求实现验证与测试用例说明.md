### BoardStatusCalculator 计算优先级（从高到低）

1. `platformStatus == "merged"` → **已合并**
2. `platformStatus == "closed"` → **已关闭**
3. 标题 Draft:/WIP: 开头 → **待 Review**
4. `hasConflict == true` → **冲突待解决**
5. CI 运行中/等待中/失败 → **CI 检查中**
6. 无 reviewer 或 approvalStatus == pending → **待 Review**
7. approvalStatus == changes_requested/reviewing → **Review 中**
8. approvalStatus == approved + mergeable == true → **可合并**
9. approvalStatus == approved + 不可合并 → **冲突待解决**
10. 默认 → **待 Review**

### CI 状态映射规则

```
GitLab:
  success/passed        → success
  failed                → failed
  running               → running
  pending/created       → pending
  canceled/cancelled/skipped → canceled
  其他                  → unknown

GitHub check-run:
  completed + success   → success
  completed + failure   → failed
  completed + cancelled → canceled
  completed + skipped   → canceled
  completed + 其他      → unknown
  in_progress/queued    → pending
  running               → running

汇总规则（多 job）：
  有 running/pending    → running
  有 failed             → failed
  仅 cancelled/skipped  → unknown
  全部 success          → success
```

## 六、拖拽变更

### 后端

`MrsController.updateStatus()` → `PUT /api/mrs/{id}/status`

校验流程：
```
@PreAuthorize (hasAnyRole ADMIN/PM/TECHLEAD/DEVELOPER)
  ↓
MR 存在性检查
  ↓
状态无变化 → 直接返回
  ↓
getCurrentUser()
  ↓
validateStatusTransition():
  ├─ REVIEWER 不可拖拽
  ├─ merged/closed → 仅 ADMIN/TECHLEAD
  ├─ 冲突 MR → 禁止 ready/merged
  └─ DEVELOPER → 仅自身 MR
  ↓
merged/closed 需调用 Git API
  ↓
写入 boardStatus + manualStatus
  ↓
recordHistory() 记录状态变更历史
  ↓
@CacheEvict 清除看板缓存
```

**manualStatus 保护机制：**

| 场景 | boardStatus | manualStatus |
|------|-------------|-------------|
| 同步后平台状态未变 | 保留手动值 | 不变 |
| 同步后平台已合并 | 改为 merged | 清除 |
| 同步后平台已关闭 | 改为 closed | 清除 |
| 再次拖拽到新列 | 更新 | 更新为新值 |

### 前端

- 原生 HTML5 Drag and Drop API（非 vuedraggable）
- `canDrag(mr)` 行级权限：REVIEWER 不可拖，ADMIN/TECHLEAD 可拖所有，DEVELOPER 仅自身
- `canDrop(mr, status)` 列级验证：冲突 MR 不可拖入 ready/merged
- 乐观更新：先更新 UI → 调用 API → 失败回滚
- merged/closed 需确认对话框
- 点击/拖拽区分：5px 位移阈值

### 预计算表 `report_daily_summary`

每个 `(summary_date, project_id)` 一行，字段：

| 字段 | 说明 |
|------|------|
| `created_count` | 当日创建的 MR 数 |
| `merged_count` | 当日合并的 MR 数 |
| `closed_count` | 当日关闭的 MR 数 |
| `avg_merge_hours` | 当日合并的 MR 平均合并时长 |
| `ci_success_count` | 当日 CI 成功次数 |
| `ci_failed_count` | 当日 CI 失败次数 |
| `conflict_count` | 当日冲突 MR 数 |

### 关键修复（历史记录）

1. **openMrCount**：从 `totalCreated - totalMerged - totalClosed`（可能负数）改为直接查询 `SELECT count(*) FROM mrs WHERE boardStatus NOT IN ('merged', 'closed')`
2. **趋势重复日期**：按日分组时增加 `dayMap` 聚合（同一日期的多项目行合并为一条）
3. **Redis 缓存**：需手动清除 `docker exec mr-board-redis redis-cli del "report:overview::current"`
