## 10. 阶段三新增技术要点

### 10.1 拖拽状态流转规则

| 原状态 | 目标状态 | 是否允许 | 额外校验 |
|---|---|---|---|
| 任意 | `merged` | 仅 TECHLEAD/ADMIN | 需二次确认，调用 Git API merge |
| 任意 | `closed` | 仅 TECHLEAD/ADMIN | 需二次确认，调用 Git API close |
| `conflict` | `ready`/`merged` | ❌ 禁止 | 返回 409，提示先解决冲突 |
| 其他内部状态 | 其他内部状态 | ✅ 允许 | Developer 仅能操作自己的 MR |

### 10.2 乐观更新与回滚策略

```
用户拖拽卡片 → 前端立即更新本地状态（乐观更新）
    │
    ▼
发送 PUT /api/mrs/{id}/status
    │
    ├──→ 成功 → 保持新状态，记录操作日志
    │
    └──→ 失败 → Toast 提示原因，卡片动画回弹到原列
```

### 10.3 Webhook 事件处理流程

```
Git 平台触发 Webhook
    │
    ▼
接收端点验签（Secret / HMAC）
    │
    ├──→ 验签失败 → 返回 401，记录日志
    │
    └──→ 验签成功 → 解析事件类型
            │
            ├──→ Merge Request 事件 → 触发对应项目的增量同步
            │
            ├──→ Push 事件 → 检查是否有关联 MR，触发同步
            │
            └──→ 其他事件 → 记录日志，忽略处理
```
