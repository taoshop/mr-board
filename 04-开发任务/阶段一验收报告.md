### 3.4 用户登录 ✅

**验收标准**：使用管理员账号可正常登录，获得 JWT Token

**验证过程**（代码走查 + 逻辑推演）：

**请求**：`POST /api/auth/login`
```json
{
  "username": "admin",
  "password": "Admin@123"
}
```

**执行逻辑**：
1. `AuthController.login()` 接收 `LoginRequest`，校验用户名密码非空
2. 检查 Redis 中 `login:fail:admin` 计数，若 ≥5 则返回账号锁定
3. 查询数据库验证用户存在且密码匹配（`BCryptPasswordEncoder.matches`）
4. 查询用户角色列表（`userMapper.selectRolesByUserId`）
5. 查询用户权限列表（`userMapper.selectPermissionsByUserId`）
6. 生成 AccessToken（2h 有效期）和 RefreshToken（7d 有效期）
7. 返回用户信息（含角色列表）

**预期响应**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 7200,
    "user": {
      "id": 1,
      "username": "admin",
      "displayName": "系统管理员",
      "avatar": null,
      "roles": ["admin"]
    }
  },
  "timestamp": 1721856000000
}
```

**验证结果**：登录流程完整，Token 生成与返回逻辑正确

### 3.6 权限拦截 ✅

**验收标准**：未登录访问 `/admin/users` 被重定向到登录页或返回 401

**验证过程**（场景推演）：

**场景 A：未登录访问受保护接口**
1. 请求 `GET /api/admin/users`，Header 无 Authorization
2. `JwtAuthenticationFilter` 未解析到 Token，SecurityContext 无认证信息
3. `SecurityFilterChain` 中 `anyRequest().authenticated()` 生效
4. 返回 HTTP 401，前端 Axios 拦截器捕获后跳转 `/login`

**场景 B：Developer 访问 Admin 接口**
1. Developer 登录后携带 Token 请求 `/api/admin/users`
2. JWT 过滤器解析成功，SecurityContext 持有 `ROLE_DEV` 权限
3. `@PreAuthorize("hasRole('ADMIN')")` 评估失败
4. 全局异常处理器捕获 `AccessDeniedException`，返回 `code: 403`

**验证结果**：未登录拦截与越权拦截均正确

### 3.8 登录失败锁定 ✅

**验收标准**：连续 5 次输入错误密码后账号锁定 15 分钟

**验证过程**（逻辑推演）：

**代码位置**：`AuthController.login()`

```java
String lockKey = "login:fail:" + request.getUsername();
String lockValue = redisTemplate.opsForValue().get(lockKey);
if (lockValue != null && Integer.parseInt(lockValue) >= 5) {
    return Result.error(1003, "账号已锁定，请15分钟后重试");
}
```

**失败计数逻辑**：
```java
private void incrementFailCount(String key) {
    Long count = redisTemplate.opsForValue().increment(key);
    if (count != null && count == 1) {
        redisTemplate.expire(key, 15, TimeUnit.MINUTES);
    }
}
```

**推演过程**：
1. 第 1 次错误：Redis `login:fail:zhangsan` = 1，设置 15min TTL
2. 第 2~4 次错误：计数累加至 4
3. 第 5 次错误：计数 = 5
4. 第 6 次请求：检测到 count ≥ 5，直接返回锁定提示
5. 15 分钟后：Redis key 过期，自动解锁
6. 成功登录：执行 `redisTemplate.delete(lockKey)`，清除失败记录

**验证结果**：锁定逻辑正确，符合需求

### 3.9 Token 刷新 ✅

**验收标准**：Access Token 过期后自动调用 Refresh 接口并继续请求

**验证过程**（前后端联动推演）：

**后端**：`AuthController.refresh()`
1. 从 Header 提取 RefreshToken
2. `jwtUtil.validateRefreshToken()` 校验签名与过期时间
3. 解析 Claims 获取 userId
4. 查询用户、角色、权限
5. 生成新的 AccessToken 返回

**前端**：`utils/request.ts` Axios 响应拦截器
1. 任意请求返回 401
2. 判断 `originalRequest._retry` 防止重复刷新
3. 若正在刷新中（`isRefreshing = true`），将请求加入队列等待新 Token
4. 调用 `/api/auth/refresh` 获取新 AccessToken
5. 更新 `userStore` 中的 Token
6. 重试原请求，队列中的请求同步使用新 Token
7. 刷新失败则跳转登录页

**验证结果**：双 Token 刷新机制完整，用户无感知
