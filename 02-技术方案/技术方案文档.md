## 2. 系统架构设计

### 2.1 总体架构

系统采用**前后端分离**架构，整体分为四层：

```
┌─────────────────────────────────────────────────────────────┐
│                        前端层 (Frontend)                       │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  MR 看板页   │  │ 统计报表页  │  │ 系统管理页（Admin）  │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
│                      Vue3 + Pinia + Element Plus               │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTPS / RESTful JSON
┌──────────────────────────▼──────────────────────────────────┐
│                      网关层 (Gateway)                         │
│              Nginx（反向代理、静态资源、负载均衡）              │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                      后端层 (Backend)                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  Auth 模块   │  │  MR 业务模块 │  │  统计报表模块        │  │
│  │  用户/权限   │  │  看板/筛选   │  │  聚合/导出          │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  Git 同步模块│  │  系统管理模块│  │  日志/监控模块       │  │
│  │  API 对接    │  │  配置/用户   │  │  审计/告警          │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
│              Spring Boot 3.x + Spring Security + JWT           │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                      数据层 (Data)                            │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────┐  │
│  │   MySQL 8.0     │  │    Redis 7.x    │  │  本地文件    │  │
│  │  业务主数据库    │  │  缓存/会话/锁   │  │  报表导出    │  │
│  └─────────────────┘  └─────────────────┘  └─────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 架构分层说明

| 层级 | 职责 | 技术组件 |
|---|---|---|
| **前端层** | 用户界面渲染、交互逻辑、状态管理 | Vue3、Vue Router、Pinia、Element Plus、ECharts |
| **网关层** | 请求路由、SSL 卸载、静态资源托管、跨域处理 | Nginx |
| **后端层** | 业务逻辑、数据校验、权限控制、外部 API 对接 | Spring Boot、Spring Security、MyBatis-Plus、Quartz |
| **数据层** | 数据持久化、高速缓存、临时文件存储 | MySQL、Redis、本地文件系统 |

### 2.3 与外部系统集成

```
本系统 Backend
     │
     ├──→ GitLab API（REST / GraphQL）←── 定时同步 / Webhook
     │
     ├──→ GitHub API（REST）←── 定时同步 / Webhook
     │
     └──→ 企业 SSO（OAuth2 / LDAP）（可选）←── 统一身份认证
```

## 3. 技术选型

### 3.1 推荐技术栈

基于 PRD 对**企业管理场景**的稳定性、可维护性、团队招聘友好度要求，推荐以下技术栈：

| 层级 | 选型 | 版本 | 选型理由 |
|---|---|---|---|
| **前端框架** | Vue 3 | 3.4+ | 国内生态成熟、学习曲线平缓、Element Plus 组件库完善、适合中后台管理系统 |
| **前端状态管理** | Pinia | 2.x | Vue 官方推荐，TypeScript 支持好，API 简洁 |
| **前端 UI 库** | Element Plus | 2.x | 企业级中后台首选，组件丰富，主题可定制 |
| **前端图表** | ECharts | 5.x | 与 Vue 集成成熟，支持丰富图表类型，可导出图片 |
| **后端框架** | Spring Boot | 3.2+ | 企业级 Java 生态标准，事务管理、安全、调度、ORM 集成完善 |
| **安全框架** | Spring Security | 6.x | 与 Spring Boot 深度集成，JWT、RBAC 支持成熟 |
| **ORM 框架** | MyBatis-Plus | 3.5+ | 简化 CRUD，分页、代码生成、多租户插件支持好 |
| **数据库** | MySQL | 8.0+ | 关系型数据为主，MySQL 在国内企业运维经验丰富 |
| **缓存** | Redis | 7.x | 会话缓存、看板数据缓存、分布式锁、同步任务去重 |
| **任务调度** | Quartz（Spring 集成） | 2.3+ | 支持 CRON 表达式、集群调度、任务持久化 |
| **报表导出** | EasyExcel | 3.x | 阿里巴巴开源，大数据量 Excel 导出内存友好 |
| **构建工具** | Maven | 3.9+ | Spring 生态默认构建工具 |
| **部署容器** | Docker | 24.x+ | 前后端统一容器化部署，环境一致性保障 |

### 3.2 备选技术栈

如团队技术储备不同，以下方案同样可行：

| 场景 | 备选方案 | 说明 |
|---|---|---|
| 前端改为 React | React 18 + Ant Design + Zustand | 适合已有 React 技术栈的团队 |
| 前端改为 Angular | Angular 17 + NG-ZORRO | 适合大型企业，TypeScript 约束强 |
| 后端改为 Node.js | NestJS + Prisma + Passport | 适合前端全栈团队，开发效率高 |
| 后端改为 Python | FastAPI + SQLAlchemy + Celery | 适合数据/AI 背景团队，异步性能优 |
| 数据库改为 PostgreSQL | PostgreSQL 15+ | 更适合复杂统计查询与 JSON 字段存储 |

## 5. 接口设计

### 5.1 统一响应规范

```json
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": 1721856000000
}
```

| 字段 | 说明 |
|---|---|
| `code` | 业务状态码：200=成功，4xx=客户端错误，5xx=服务端错误 |
| `message` | 提示信息 |
| `data` | 响应数据（可为对象、数组、分页结构） |
| `timestamp` | 服务端时间戳 |

**分页响应结构**：
```json
{
  "code": 200,
  "data": {
    "list": [ ... ],
    "pagination": {
      "page": 1,
      "size": 20,
      "total": 156,
      "pages": 8
    }
  }
}
```

### 5.2 认证模块接口

#### 5.2.1 用户登录

```http
POST /api/auth/login
Content-Type: application/json
```

**请求体**：
```json
{
  "username": "zhangsan",
  "password": "plain_password"
}
```

**响应**：
```json
{
  "code": 200,
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 7200,
    "user": {
      "id": 1,
      "username": "zhangsan",
      "displayName": "张三",
      "avatar": "https://...",
      "roles": ["dev"]
    }
  }
}
```

#### 5.2.2 刷新 Token

```http
POST /api/auth/refresh
Authorization: Bearer {refreshToken}
```

#### 5.2.3 获取当前用户

```http
GET /api/auth/me
Authorization: Bearer {accessToken}
```

**响应**：
```json
{
  "code": 200,
  "data": {
    "id": 1,
    "username": "zhangsan",
    "displayName": "张三",
    "avatar": "https://...",
    "roles": ["dev"],
    "permissions": ["mr:read", "mr:update:self", ...]

}
```

### 5.3 MR 模块接口

```http

Authorization: Bearer {accessToken}
```

| 参数 | 类型 | 说明 |
|---|---|---|
| page | int | 页码，默认 1 |

| projectId | long | 项目 ID（可多选，逗号分隔） |
| authorId | long | 提交人 ID（可多选） |
| reviewerId | long | Reviewer ID（可多选） |
| status | string | 看板状态（多选，逗号分隔：1,2,3） |
| ciStatus | string | CI 状态（多选） |

| label | string | 标签筛选 |
| keyword | string | 关键词（匹配标题、描述、MR 编号） |
| createdStart | string | 创建时间起始（ISO 8601） |
| createdEnd | string | 创建时间结束 |

### 6.2 看板状态映射算法

```java
public BoardStatus calculateBoardStatus(MR mr) {
    // 已合并 / 已关闭直接映射
    if (mr.platformStatus == MERGED) return BoardStatus.MERGED;
    if (mr.platformStatus == CLOSED) return BoardStatus.CLOSED;

    // 冲突检测优先
    if (mr.hasConflict || !mr.mergeable) return BoardStatus.CONFLICT;

    // CI 状态检查
    if (mr.ciStatus == CIManager.RUNNING || mr.ciStatus == CIManager.PENDING) {
        return BoardStatus.CI_CHECKING;
    }

    // Review 状态检查（基于评论/Approval 缓存）
    if (mr.reviewers != null && !mr.reviewers.isEmpty() && mr.commentsCount > 0) {
        return BoardStatus.IN_REVIEW;
    }

    // 默认可合并或待 Review
    if (mr.ciStatus == CIManager.SUCCESS && mr.mergeable) {
        return BoardStatus.MERGEABLE;
    }

    return BoardStatus.PENDING_REVIEW;
}
```

### 6.4 统计报表聚合 SQL 示例

**平均合并时长（按周）**：
```sql
SELECT
  DATE_FORMAT(created_at, '%Y-%u') AS week,
  COUNT(*) AS total_merged,
  AVG(TIMESTAMPDIFF(HOUR, created_at, merged_at)) AS avg_merge_hours,
  PERCENTILE_CONT(0.5) WITHIN GROUP (
    ORDER BY TIMESTAMPDIFF(HOUR, created_at, merged_at)
  ) AS median_merge_hours
FROM mrs
WHERE platform_status = 2  -- merged
  AND created_at BETWEEN '2026-07-01' AND '2026-07-31'
GROUP BY DATE_FORMAT(created_at, '%Y-%u');
```

> 注：MySQL 8.0 原生不支持 `PERCENTILE_CONT`，需在应用层计算中位数或使用窗口函数变通实现。

## 7. 安全设计

### 7.1 认证与鉴权
- **JWT Token**：Access Token 有效期 2 小时，Refresh Token 有效期 7 天
- **Token 刷新**：前端在 Access Token 过期前自动调用 `/api/auth/refresh`
- **密码安全**：用户密码使用 bcrypt（salt rounds = 12）加密存储
- **登录安全**：支持登录失败次数限制（5 次/15 分钟），超限锁定账户

### 7.2 权限控制
- **URL 级拦截**：Spring Security 配置角色访问规则（如 `/api/admin/**` 仅 ADMIN）
- **方法级注解**：`@PreAuthorize("hasPermission(#mrId, 'MR', 'UPDATE')")`
- **数据级隔离**：查询时自动附加 `project_id` / `author_id` 过滤条件

### 7.3 敏感信息保护
- **Token 加密**：Git API Access Token 使用 AES-256 加密后存入数据库，密钥通过环境变量注入
- **HTTPS 强制**：生产环境全站 HTTPS，HSTS 头配置
- **日志脱敏**：日志中不打印 Access Token、用户密码等敏感字段

### 7.4 操作安全
- **敏感操作确认**：合并/关闭 MR 操作需前端二次确认弹窗
- **操作审计**：所有状态变更记录 `mr_status_history`，包含操作人、时间、IP 地址
- **Git API 操作幂等**：合并/关闭操作前校验当前平台状态，防止重复执行

## 8. 性能与扩展设计

### 8.1 性能优化策略

| 优化点 | 方案 |
|---|---|
| 看板查询 | Redis 缓存用户看板数据（TTL 2 分钟），减少数据库压力 |
| 列表分页 | 数据库分页 + 覆盖索引，避免深分页问题（限制最大 1000 条） |
| 报表计算 | 定时任务预计算日报/周报数据，写入报表汇总表，查询时直接读取 |
| 同步性能 | 增量同步基于 `updated_at` 或 Webhook，全量同步分批次（每批 100 条） |
| 大数据导出 | EasyExcel 流式写入，分页查询（每批 500 条），避免 OOM |
| 前端渲染 | 虚拟滚动加载看板卡片（单列超过 50 条时分段加载） |

### 8.2 扩展性设计
- **多 Git 源**：`git_sources` 表支持配置多个平台，同步任务按源隔离执行
- **多项目**：通过 `project_id` 天然隔离，后续可按项目分库分表
- **插件化同步**：Git API 客户端抽象接口（`GitSyncClient`），新增平台只需实现接口
- **前后端独立扩展**：前端静态资源可部署至 CDN，后端服务可水平扩展
