## 2. 测试概述

### 2.1 测试目的
验证 Git MR 看板系统是否满足《系统 PRD 文档》与《技术方案文档》中定义的全部功能需求、性能指标、安全规范，确保系统达到上线标准。

### 2.2 测试范围

| 范围类型 | 具体内容 |
|---|---|
| **包含范围** | 用户认证与权限、Git 源配置、MR 数据同步、看板展示、多维筛选、拖拽状态变更、CI 状态集成、冲突标识、MR 详情、统计报表、报表导出 |
| **包含范围** | 性能测试（并发、大数据量）、安全测试（鉴权、注入、XSS）、兼容性测试（浏览器、分辨率） |
| **排除范围** | 生产环境部署验证、第三方 Git 平台 SLA 保障、移动端浏览器适配 |

### 2.3 测试策略
- **功能测试**：基于《测试用例.md》逐条执行，覆盖正向流程与异常流程
- **接口测试**：使用 Postman / JMeter 对接口进行参数边界、异常响应验证
- **性能测试**：JMeter 模拟并发用户，监控响应时间与系统资源
- **安全测试**：手工注入测试 + 代码审计（Token 加密、权限校验）
- **兼容性测试**：多浏览器、多分辨率人工验证

### 6.2 缺陷明细

| 缺陷编号 | 所属模块 | 严重程度 | 缺陷描述 | 状态 | 备注 |
|---|---|---|---|---|---|
| BUG-001 | Git 源同步 | 一般 | 当 GitLab 项目路径含中文时同步报错 `InvalidPathException` | 已关闭 | 修复：对项目路径进行 URL 编码 |
| BUG-002 | 拖拽状态变更 | 严重 | Tech Lead 拖拽 MR 到"已合并"列时，Git API 调用失败后本地状态未回滚，卡片停留在"已合并" | 已关闭 | 修复：增加事务回滚，Git API 失败时恢复本地状态 |
| BUG-003 | CI 状态集成 | 一般 | GitHub Actions 的 CI 状态映射错误，将 `skipped` 映射为"成功" | 已关闭 | 修复：增加 `skipped` → "取消" 的映射分支 |
| BUG-004 | 统计报表 | 一般 | 跨周时间边界（如周日 23:59 创建的 MR）在周统计中归属错误 | 已关闭 | 修复：统一使用服务器时区（Asia/Shanghai）进行日期归属计算 |
| BUG-005 | 性能测试 | 轻微 | 看板页面在 1000+ MR 时首次加载前端 JS 执行耗时 3.8 秒 | 已关闭 | 修复：启用路由懒加载 + 组件按需引入，优化至 2.1 秒 |
| BUG-006 | 多维筛选 | 轻微 | 关键词搜索框输入特殊字符 `$` 时前端报错 `Invalid regular expression` | 已关闭 | 修复：对关键词进行正则转义处理 |
| BUG-007 | 拖拽状态变更 | 一般 | 同一 MR 被两个用户同时拖拽时可能出现状态覆盖（竞态条件） | 已修复待验证 | 修复：增加数据库乐观锁（version 字段） |
| BUG-008 | 统计报表 | 严重 | 大数据量（>5000 条）导出时，平均合并时长计算结果与数据库 SUM/COUNT 存在 0.3% 偏差 | 延期处理 | 原因：浮点数精度丢失，计划下一迭代改用 BigDecimal 精确计算 |

## 9. 代码审查专项测试（ST 第 2 轮）

### 9.1 测试概述

本轮测试由 **PR #4 代码审查（`/code-review` high effort）** 触发，聚焦于审查过程中发现的 4 个新增缺陷。这些缺陷涉及 MR 数据同步的时区处理、分页失败容错、GitHub 状态映射边界条件，虽在 ST 第 1 轮未直接暴露，但属于可触达的线上风险。

| 项目 | 内容 |
|---|---|
| **触发原因** | PR #4 `fix/sync-status-accuracy` 代码审查 |
| **审查方式** | 8 角度独立扫描 + 1 票验证（recall-biased） |
| **发现缺陷** | 4 个（2 个 CONFIRMED、2 个 PLAUSIBLE） |
| **测试日期** | 2026-07-26 |
| **新增用例** | TC-SYNC-009 ~ TC-SYNC-012（见《测试用例.md》v1.1） |

### 9.2 新增缺陷明细

| 缺陷编号 | 所属模块 | 严重程度 | 缺陷描述 | 状态 | 关联代码位置 | 审查结论 |
|---|---|---|---|---|---|---|
| BUG-009 | Git 源同步 | **严重** | `SyncService.doSync` 使用 `LocalDateTime` 生成 `updatedAfter` 并硬拼 `"Z"`，在 non-UTC 服务器上导致时间戳被 Git 平台误解为 UTC，增量同步跳过近期 MR | 新发现 | SyncService.java:125-127 | CONFIRMED |
| BUG-010 | Git 源同步 | **严重** | `GitHubClient.fetchMRs` 分页失败时 catch 并 break，返回部分数据；`SyncService.doSync` 未感知失败，标记 success 并更新 `lastSyncAt`，导致未拉取的 MR 永久丢失 | 新发现 | GitHubClient.java:83-86 / SyncService.java:152-158 | CONFIRMED |
| BUG-011 | Git 源同步 | 一般 | `GitHubClient.convertToDto` 将 `mergeable` 改为 `!"closed".equals(pr.get("state"))`，当 state 为 null 时结果为 true（原代码 `"open".equals(null)` 为 false），导致异常响应中的 PR 被错误标记为可合并 | 新发现 | GitHubClient.java:226 | CONFIRMED |
| BUG-012 | Git 源同步 | 轻微 | `mapGitHubState` 仅检查 `merged_at != null`，未校验空字符串，若 merged_at="" 会将未合并的 closed PR 误判为 merged | 新发现 | GitHubClient.java:242 | PLAUSIBLE |

### 9.3 修复建议

| 缺陷编号 | 修复方案 | 预估工作量 |
|---|---|---|
| BUG-009 | 将 `LocalDateTime` 替换为 `OffsetDateTime`（或 `ZonedDateTime`），使用 `DateTimeFormatter.ISO_OFFSET_DATE_TIME` 生成 `updatedAfter`，确保时区信息准确传递至 Git 平台 | 0.5 人天 |
| BUG-010 | ① `GitHubClient.fetchMRs` 在分页失败时抛出 `SyncPartialFailureException`；② `SyncService.doSync` 捕获该异常后标记 sync log 为 failed，**不更新** `lastSyncAt`；③ 已入库的部分数据由下次全量同步覆盖修正 | 1 人天 |
| BUG-011 | `mergeable` 逻辑恢复为 `"open".equals(state)`，或在现有逻辑前增加 `state != null` 前置检查，确保 null/缺失 state 时默认不可合并 | 0.5 人天 |
| BUG-012 | `mapGitHubState` 中增加 `merged_at` 非空字符串校验：`(mergedAt instanceof String && !((String) mergedAt).isBlank())` | 0.5 人天 |
